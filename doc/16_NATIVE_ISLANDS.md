# 原生结构岛与导出防护

## 已验证的故障链

2026-09-28 的 `981.1.data` 样本含两个物理载具。主载具有 96 个节点、184 根梁、87 个面板；其中节点 99 和 100 被面板引用，却没有任何相连的梁。节点编号仅记录故障证据，修复代码不使用这些编号或文件名。

崩溃报告 `crash-2026-09-28-153708-32024.json` 的 UTC 时间为 `2026-09-28T15:37:09Z`，位置为 `server_scene.vehicle._split_islands + 1871`。与本次本地 `game.gcl` 匹配后，故障指令是文件偏移 `0x31c350d` 的 `mov rax, [rax]`，寄存器 `rax = 0`。前面的代码对节点 `+0x60` 处的梁列表调用 `front()`，随后取第一根梁的 `+0x118` 岛编号，没有空列表分支。无相连梁的节点满足此次空指针故障条件。

来源指纹、10 个函数记录、重定位名称及关键指令见 [审计摘要](evidence/native-islands.json)。可用以下只读命令复核本地同版本游戏文件；脚本不启动游戏，也不修改存档：

```powershell
node scripts/check-native-island-evidence.mjs <Anymaker/bin/game.gcl>
```

## 游戏遍历规则与当前实现

已静态核对 `_flood_island`、四个 `_flood_islands` 重载、`_rebuild_islands`、`_reset_island_indices`、`_split_islands`、`find_edge` 与面板邻接重建记录：

| 对象 | 游戏遍历对象 | 编辑器对应处理 |
| --- | --- | --- |
| 梁 | 两端节点上的其他梁，以及登记的面板和组件 | 通过相同节点 ID 连接梁；不以坐标接近替代节点引用 |
| 面板 | 实际边界梁引用，以及登记的组件 | 按相邻边界节点的无序 ID 对查找梁；缺梁不自动连接该角节点上的任意梁 |
| 组件 | 登记的梁、面板和组件 | 沿用安装面与专用接口的静态接触近似 |
| 节点 | 拆岛时由第一根相连梁取得归属 | 检查面板角节点至少有一根梁，并检查角节点与面板归属一致 |

信号网络和物理关节不直接构成刚性岛连通边。多个岛可以合法存在；不能为了消除岛数而焊接所有结构。梁不要求每个端点都接触组件，有效结构外壳可以独立存在。

`src/editor/structural-topology.js` 负责结构 ID、坐标、引用、退化/重复梁、面板几何和实际边界梁分析。`src/editor/subgrid-connectivity.js` 在遍历后检查面板是否跨岛引用节点。缺失部分边界梁本身报告警告；面板角节点无梁、跨岛引用等安全错误阻止应用子网格划分。节点标记和中英文诊断提供定位。

## 通用导出规则

`toNativePairFromEditor` 在物理多体划分前规范化临时结构副本，再运行与按钮相同的结构岛预检：

1. 沿用已有共线孤点清理，只移除位于相邻边界点之间、且没有梁引用的冗余点。
2. 对仍无梁支撑的面板角节点，补全其相邻面板边界梁。按无序节点对去重；已有梁保留原色，新梁使用面板前侧颜色，缺失时使用后侧颜色。
3. 对已经有梁的节点，不盲目补全所有三角剖分边；面板跨岛引用仍须显式修正。
4. 预检发现重复 ID、退化梁、非法面板、跨岛引用或悬空连接时拒绝导出。分体后再次验证每个载具的节点、梁和面板引用，以及每个导出节点都有相连梁。
5. 规范化仅影响导出副本；当前工程、历史与磁盘原文件不被隐式改写。

`tests/native-export.test.js` 使用独立合成数据覆盖无梁角点、共享边去重、节点重编号/重排、绕序反转、全部缺梁、跨岛拒绝、物理多体和往返幂等性。`tests/browser/editor.spec.js` 覆盖中英文错误、节点定位、下载后重新导入及失败时保留工程。单元测试由现有 `tests/unit.test.js` 入口引入。

## 验证边界

对原报错文件执行内存中的导入、导出和再次导入后，主载具变为 189 根梁，节点与面板数量不变；第二载具仍为 9 个节点、12 根梁、4 个面板。各载具均无悬空结构引用或无梁节点，物理配合的载具/组件引用有效，原 `.data/.meta` 文件 SHA-256 未改变。复核结果为 0 个错误、3 个缺失边界警告、2 个合法结构岛，不能把“无错误”写成“无任何诊断”。

2026-09-28 实际执行：`npm run check` 的 231 项单元测试及生产构建通过；`npm run test:browser:editor` 的 94 项编辑器流程通过。随后补充编号重合定位修复，并重跑 3 项结构岛相关浏览器流程通过。证据脚本成功核对 10 个 GCL 函数记录及 4 处关键指令。构建仍有大于 500 kB 的 chunk 提示，本次未修改打包策略。

当前证据适用于摘要指纹对应的 GCL 版本。组件接触登记的全部几何容差、运行时破坏/脏标记与拆岛调度尚未完整复刻；静态接触近似仍可能与游戏不同。此次没有启动游戏加载导出文件，没有完成动态物理或游戏兼容性验收。
