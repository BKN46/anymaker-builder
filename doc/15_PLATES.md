复核日期：2026-09-28。结论来自当前源码、原生样本、只读 GCL 机器码与选定反编译结果；没有运行游戏或完成同机位截图验收。

## Review 结论

| 优先级 | 发现 | 当前处理 |
| --- | --- | --- |
| P1 | 原渲染把完整镜头方向用于选择每个节点立方体的角。正视时扩张轮廓，斜视时整片横移；相同节点环因创建视角不同得到不同几何。 | 内部面改为按面法线计算统一表面偏移，镜头只决定正反面。 |
| P1 | 对未闭合的草稿提前做凸性、共面、尺寸及端点连续性检查，会阻碍合法边界的选择。 | 按用户要求允许任意顺序选梁，包括共线分段、不同梁宽及暂时不相连的边；只在形成单一闭环后校验共面、同一子网格及有效边界。无四梁上限。 |
| P1 | 原选梁射线只检测梁，能穿过前景面板和组件。 | 悬停和点击共用最近实体命中，再检查候选。尚未完整复现游戏所有 raycast filter。 |
| P1 | 单层多边形几何缺少游戏的厚度、外沿条带及窗内框。 | **仍未完成**。本轮仅修正内部面的轮廓和表面位置，不称为完整游戏 plate mesh。 |
| P2 | 原校验没有检测自交，共面误差随叉积长度改变；扇形三角化会填满某些凹面缺口。 | 共面使用单位法线距离，最终闭环拒绝自交/回折；新建、旧工程及导入的简单凹面均采用耳切三角化。 |
| P2 | 重复边界检查对循环起点的索引不正确，换一根梁开始可能漏过重复面。 | 修复循环移位及反向绕序的去重。 |
| P2 | 结构面文案混用 Plate、Panels，模型导入和涂色提示也不一致。 | 结构面统一为 Plate / plates；数学平面仍为 plane，设置面板仍为 panel。 |

静态 GCL 证据确认，游戏建造工具在 `state_add_plate_select_edges` 阶段调用 `_get_is_planar`、`_get_is_convex`，闭环提交前再调用 `client_scene.vehicle.can_add_plate`；已定位的加载几何入口 `vehicle_plate_util.add_static_geometry` 接收节点列表后直接计算法向、厚度偏移并分派 `solid/window` 等几何分支，没有发现同一处 `can_add_plate` 调用。这支持通过 JSON 节点环绕过建造候选检查的方案，但单一加载入口不能证明所有运行时检查都不存在。2026-10-02 用户反馈曲面原生导出已成功载入游戏，适用于其验证样本，不扩展为任意曲面兼容承诺。

plate-toolbar/window-toolbar 各自提供“规避游戏曲面限制”。启用后新面保存 `surfaceLimitBypass: true`，允许非平面边界和重复边界。几何在 XY/XZ/YZ 及整体边界法向的投影中选择面积最大的简单轮廓，执行自交检查，顶点仍保留原始三维位置。2026-10-06 创建旁路面后自动识别有限双平面并生成一个原生扇形：从已有边界节点寻找折线及两侧共面区域，避免普通耳切跨折线而误判平面数；再检查原生扇形的逐平面面积、外梁和内缩几何。不能构建时直接报错并保留原项目，不新增内部梁或节点。标记仅保存在编辑器工程，原生文件仍使用标准 `plates[].nodes`、`type: window` 等字段；节点引用、结构岛及导出边界梁检查继续执行。

窗口碰撞/破碎、外沿与内框、阻挡体和任意非凸曲面的运行时行为仍未验证。普通编辑器三角化与游戏三角化不必相同；旁路单面预览使用已复现的原生扇形及内缩路径。下面的显式分片为历史方案，必须满足游戏逐面边界梁检查才能导出。

## 曲面分片历史（2026-10-02）

2026-10-06 已暂时移除此功能的工具栏、Inspector 和交互入口。以下记录旧版操作及研究边界，不表示当前 UI 可用；纯数据模块、旧工程及回归用例仍保留。当前入口为自动“双平面单面”，详见 [18 曲面研究](18_WINDOW_FAN_RESEARCH.md#编辑器接入2026-10-05)。

采用多边形建模的 Connect Vertices / Split Face 操作和 CAD 分段放样的截面对应思路。单一边界环不能唯一确定内部曲面；用户连接两侧对应折点，显式决定分段关系。支持通过已有同网格三维节点的折线；未实现 NURBS、任意内部点自动拟合或参数化曲率。

1. 选中一个非平面或带旁路标记的 plate/window，在属性中点击“曲面分片”；或在旁路工具栏点击同名按钮，再点击曲面。未启用旁路的普通平面没有该入口。
2. 选择起点和终点，可从“途经节点”依次添加同一网格已有的空间节点，点击“连接节点”建立“起点→途经点→终点”的折线。起终点必须在同一待分区域边界上；前一条折线加入的节点可以作为后续折线端点。橙色线表示手动约束，半透明面显示分片后的预览。
3. 可以撤回最后一条线；取消、Esc、切换工具或恢复历史会丢弃草稿并恢复原曲面。草稿不进入工程、导出或历史。
4. “应用分片”将原面替换为各个凸平面区域；剩余非平面或凹区域会逐片三角化。保留已有梁、节点位置、窗类型和正反颜色，不添加分界梁，形成一个可撤销操作。保留旁路标记，允许进一步空间编辑，并禁止原生导出自动为它补梁。若区域仍无法三角化，保留连线草稿并要求继续细分，不提交无效面。

初版自动创建分界梁的行为已撤除。连线只决定面片的共享边界，预览标明“不新增梁”，同时报告缺失边界梁的面片数量。这类形状可以保留在工程中编辑，但原生导出会报错，因为游戏创建入口会丢弃它们。即使补齐边界梁，游戏仍为每片窗生成窗框，当前透明预览尚未显示这些框线。工具未开启时不增加节点拾取、不改变普通工具快捷键、选取及建造行为。

纯数据实现见 [surface-split.js](../src/editor/surface-split.js)、[surface-paths.js](../src/editor/surface-paths.js)，交互与预览释放见 [surface-split-tool.js](../src/editor/surface-split-tool.js)。普通边界弦保留原有投影检查；含额外节点的空间路径按拓扑切分区域，按三维线段距离拒绝实际交叉/重叠，不以二维投影交叉代替空间交叉。校验还拒绝重复/缺失节点、跨网格、非法端点或将已有边界节点当作新途经点；失败保留原项目。当前要求起始面可由既有边界校验表示，每个最终区域能单独三角化；这不是对任意闭合三维壳体、带孔曲面或所有面片间自碰撞的通用求解器。

最新只读样本 `anymaker-vehicle.data` 为 5,826 字节，SHA-256 `7bd0ec9eb00bf26c02bda2c6b1d75d99f4cdd2c49b6196678ae552b896b73879`，含 12 节点、15 梁、8 个三角窗。导入及旧版再次导出都保留全部 8 个窗记录，排除了编辑器导出删除的猜测；每一片至少缺一条边界梁，符合游戏创建失败条件。新的导入保留全部面并显示警告，导出明确拒绝，源 data/meta 哈希不变。详细缺边列表在 `tmp/curved-surface-followup/sample-report.json`。

历史验证：此前 251 项单元测试、构建及四项曲面浏览器流程通过，只证明编辑器内往返，不能证明无内部梁分片能加载游戏。`exports/anymaker-vehicle-no-internal-beams.data/.meta` 是已被加载代码否定的旧实验副本，不能作为有效方案。新的外边界恢复副本 `exports/anymaker-vehicle-outer-boundary-recovery.data/.meta` 将这 8 片合回节点环 `[12,7,1,6,5,4,3,9,10,11]`，保持 12 节点、15 梁和窗类型，通过边界加载预检；**不保留内部约束**，尚未实机验证。

验收目标是原版游戏中保留手动连接指定的曲面形状，连续窗面没有新增分界梁或内部窗框。导出报错只能防止已知的静默丢面，**不算完成该目标**。单纯取消编辑器报错也不会改变游戏加载和几何生成。

| 尝试方向 | 新查明的代码事实 | 对目标的影响 |
| --- | --- | --- |
| 用零尺寸保留逻辑梁、隐藏分界梁 | `vehicle_edge_util.add_static_geometry`（`0x3be7c54`）默认宽度取 `G_GRID_SIZE`，仅 `size == 1` 时乘三；`size == 0` 是正常宽梁。边数据解析（`0x313a30d`）只读 `n0/n1/col/size`。 | 零尺寸不是隐藏梁开关。客户端梁几何入口（`0x122aae5`）对缺端点或重合端点不生成几何；重合端点也会使目标面片边界塌缩。 |

| 利用透明调色板像素隐藏框 | 从 `pipeline_vehicle_plates_edges.create_pipeline`（`0x23a51d2`）和深度管线（`0x23acdf8`）提取四个 DXBC，用 Windows `d3dcompiler_47.dll` 的 `D3DDisassemble` 反汇编。表面像素着色器采样调色板并输出法线、深度，没有 `discard` 或 alpha test；深度像素着色器根本不采样调色板。 | 不能把 `col=255` 当作可靠的无几何/无遮挡标志；完整合成结果仍未实机验证。 |

着色器的深度输出使用 `inputDepth * (0.998 + 0.004 * (depth_layer + colorIndex / 255))`。这说明颜色还影响深度偏移；没有尝试把越界颜色当作生产导出方案，也没有证明这种数值扰动能同时消除遮挡、窗间缺口和物理梁。以上是在已核对路径上排除具体候选，不是对所有可能漏洞的不存在证明。

对当前样本作了独立几何比较：从八片目标三角窗提取外环，循环尝试十个扇心；在 `(y,z)` 域内按 `121 × 81` 网格采样，对比目标分段轮廓与节点扇形的 `x`。节点 5 或 11 为扇心时，最大采样偏差约 **0.139835 游戏世界单位**，均方根偏差约 **0.060239**（按每格 0.08 世界单位换算）。这不是实机测量，不包含窗内缩、统一表面偏移、厚度以及投影退化而空间面积非零的侧三角形；最大采样值也不是严格误差上界。不能将其标记为原生玻璃的精确误差或可接受方案。详细结果保留在 `tmp/seamless-surface-research/fan-comparison.json`。

## 重叠窗与负颜色深度探针（2026-10-02，继续研究）

本轮继续寻找存档层面的可用入口，没有把关闭导出预检或丢弃约束作为实现方案。新增结果如下。

### 重叠完整边界窗

候选思路是多个窗共用完整外边界，各自选择不同扇心，利用外层包络构成目标曲面。每片都能引用原有边界梁，框也只沿外边界生成；但这要求渲染只显示最外层。

`pipeline_vehicle_glass.create_pipeline`（`0x231cdab`）的管线描述符设置 `m_blend_mode = 3`、`m_is_depth_read = true`、`m_is_depth_write = false`、`m_compare_func_depth = 4`。GCL 类型元数据确认枚举 3 是 `premultiplied_alpha`，比较枚举 4 是 `greater`。玻璃像素着色器直接计算透明混合所需的颜色与 alpha，没有选择曲面包络的步骤。因此重叠的玻璃层仍会参与混合，不能把多扇心窗的几何包络当作实际显示结果。未把它接入导出。

另一个更早阶段的差异是 `calculate_plate_dir`（`0x3c42721`）：它固定第一条边，寻找后续首条与之不平行的边，以叉积决定整体法线，不是整个环的平均法线。样本正向外环有六个起点得到 Z 轴法线、进入一轴窗算法，四个得到 XY 法线、进入二轴算法。上一轮原始节点扇形采样的最佳起点 5、11 恰好属于一轴分支，不能把那个误差排序当作实际玻璃排序。一轴算法还有内沿交点重建；二轴/三轴也有内缩，完整游戏几何不能直接用原始节点扇形代替。二十种起点/绕序的法线结果在 `tmp/curved-window-overlap/order-normal-audit.json`。

### 新候选：用有符号颜色影响深度

上一轮只核对了常规调色板的空颜色 255。本轮补齐了深度比较的枚举含义：梁/面板管线使用反向深度 `greater`，颜色属性以 `s32` 上传，顶点着色器作有符号 `itof`，片元深度公式是：

```text
depth = inputDepth * (0.998 + 0.004 * (depth_layer + colorIndex / 255))
```

当前载具绘制调用的层号为 -1、0、1。探针颜色取 `-1048576`，层号 0 的乘数约为 `-15.450251`，其它两层也为负。**静态预测**是这些梁和可涂色面片的深度无法通过反向深度比较，而窗的透明三角形走独立玻璃管线。这个入口与 `col=255` 不同，尚未通过真实游戏画面确认；存档再保存、拾取和物理行为也待验证。

继续追踪确认了它的范围限制：`client_scene.vehicle._rebuild_geometry_plates_edges`（`0xee4b55`）每次以 RGB `(16,16,16)` 在全局调色板中查找固定内框颜色，传给 `client_scene.vehicle_plate.add_static_geometry`，最终作为窗算法的独立框色。它不来自 `plates[].col_front/col_back`。所以即使负颜色成功隐藏结构梁和可涂色边沿，固定深灰内框仍预计存在，玻璃内缩的缝隙也未自动补齐。隐藏渲染还不等于删除物理梁，不能视为完成用户目标。

### 可复现的独立探针

新增离线脚本 [create-window-depth-probes.mjs](../scripts/create-window-depth-probes.mjs)，读取 `.data/.meta`，只为缺梁窗创建独立实验副本；不改编辑器、普通导出、原存档或游戏。命令：

```powershell
node scripts/create-window-depth-probes.mjs <vehicle.data> [output-directory]
```

脚本拒绝缺失节点、重复面节点及非窗面的缺梁输入，对共享边去重；保留未知字段、节点位置、面片节点顺序和原有梁。输出新建的随机后缀目录，附原文件与各变体哈希、验证范围和操作说明。它有意直接写入实验负颜色，不能经当前 Builder 的普通调色板流程往返后再拿来验证。

当前样本输出到 `exports/window-depth-probes-KrhfMm/`，三组均为 12 节点、22 梁、8 个原始三角窗，原来缺失的七条边界全部补齐：

| --- | --- |

## 已验证的静态代码事实

[早期证据摘要](evidence/plates.json) 记录 11 个函数的签名、代码/分配范围、代码哈希和重定位列表。该轮输入为 bin/game.gcl，81,870,449 字节，SHA-256 为 d9725681f1b0bff321c58fcadc0d2e12104919a541eef074cf12945b283edb75。它与旧 native-grid-transform.json 的 32c138… 版本不同，因此该轮重新解析函数记录，并核对代码后的所有者名称，未沿用旧偏移。当前安装版本请使用上节的新摘要。

选点问题的具体区别是**梁链的节点拓扑及候选规则**，不能据此认定游戏允许任意点选独立节点：

- state_add_plate.tick 从命中的梁建立草稿，同时存入该梁两端节点 ID。
- state_add_plate_select_edges.get_is_edge_visible 检查梁端是否连接节点链的首尾，并调用 _get_is_planar、_get_is_convex。
- state_add_plate_select_edges.tick 支持向链首或链尾插入节点。闭合时调用 client_scene.vehicle.can_add_plate，再发送节点列表、朝向标记和 plate 类型。
- _get_is_convex 将节点位置交给 vehicle_util.test_is_convex。这是游戏静态代码证据；当前编辑器按用户要求去掉选取时的凸性等前置过滤，不把该游戏候选规则作为编辑器限制。

渲染路径中，add_static_geometry 调用 get_plate_node_surface_offset，另用 G_VEHICLE_PLATE_THICKNESS 计算背面偏移，再按 solid/window/opening/hatch 分派，并调用 add_geometry_outer。add_geometry_inner_solid 将同一个节点表面偏移加到每个节点，分别提交正反三角面。偏移取决于法线的非零轴：一轴取立方体面中心，两轴取最外侧边中点，三轴取最外侧角；与镜头的切向分量无关。

本轮没有实现 add_geometry_outer_1_axis/2_axis 的全部外沿、边框、窗口孔洞和厚度规则，也没有把游戏对凸形使用扇形三角化解释为对任意凹形安全。诊断材质、窗透明度和光照仍与原游戏不同。

## 当前实现与数据边界

- [plate-selection.js](../src/editor/plate-selection.js) 收集所选梁集合，悬停和点击调用同一逻辑。再次点击取消单条梁，Esc 清空。暂未相连、共线、混合宽度、不共面和跨网格的草稿都可以继续编辑，不提前当作封闭多边形校验。全部所选梁组成单一闭环时才排序节点，并校验梁及明确归属的节点在同一子网格；普通工具要求共面，旁路工具允许非平面但执行参考平面投影后的退化和自交检查，随后创建面板或窗。分支和多个不连通环不提交；自交、回折或退化闭环报错且保留原草稿及工程。中间共线节点保留在工程边界引用中，三角化可略过冗余共线点。草稿不写入工程，闭合才提交一个可撤销操作。隐藏节点辅助不会清除选梁草稿。
- [plate-polygon.js](../src/editor/plate-polygon.js) 共用平面投影、自交校验及三角化；领域层不引入 Three.js。
- 拖动节点暂时造成普通 plate 不共面或自交时，仅隐藏无效预览；旁路 plate 允许非平面但仍在投影退化或自交时隐藏。恢复有效轮廓后重新显示；共线节点使三角形数量变化时同步更新法线及正反面材质组，提交仍执行领域校验。
- construction-view.js 的内部面以节点环加统一支撑偏移渲染。轴向面的轮廓不再凭空扩大半格；外侧梁面因而更明显，这是尚未实现独立外沿条带的可见边界。
- 工程 schema 仍为 v1。已有 surfaceDirection 保留，但只用于判断法线正负；新建时保存带正反方向的单位法线。旧文件不需要删字段，重新渲染的轮廓会按修正规则变化。
- normalOffset 继续保留为世界单位的可选偏移参数；在本次内部面实现中，其绝对值用于每个非零法线轴的支撑偏移。普通新建值为 0.04，三格宽梁为 0.12；混合梁宽取所选梁的最大宽度，因此不依赖点击顺序。零值保持在节点面。该参数不是游戏 plate 厚度。
- 新面归属跟随所选梁链，避免把非当前子网格上的面错误写入 active grid。此处 grid 是编辑器物理分组，不把原生安装坐标网格当作独立刚体。
- 原生导出仍按既有 X 反射及节点绕序映射正反面。修正内部渲染不代表原生存档已获得游戏加载验收。
