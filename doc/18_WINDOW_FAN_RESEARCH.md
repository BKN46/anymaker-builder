## 多片三角窗为什么仍有接缝

二/三轴三角窗使用的常量已按当前字节重新核对：格长 `0.08`、plate 厚度 `0.01`、窗内缩 `0.5 × 格长 = 0.04`、额外内框宽度 `0.01`。因此玻璃边界相对该片支撑后的原边界向内缩 **0.05**，即 **0.625 格**。

在普通建模软件中，相邻三角形可以共用顶点和边，从而成为同一块连续网格。游戏 window 是每面独立生成的带孔几何：两片即使共用同一节点和梁，玻璃也会分别退到边的两侧。两个共面窗的玻璃边界相距 `2 × 0.05 = 0.10`，即 **1.25 格**；中间由各自的窗框填充。隐藏梁或改变涂色无法扩大玻璃孔洞。

多个三角形放在同一原生窗里时，游戏内部的扇形对角线不需要实际梁，也不会为这些内部对角线单独生成窗框。这条路径能表达**符合单扇形的曲面**。它仍只支持一个扇心，不能保存任意三角分片连接。

### 单窗合并为什么改变目标形状

目标八个三角形分属四个平面。若一个扇形精确覆盖这些有面积的平面片，它的扇心必须同时位于四个平面上。这一必要条件不要求扇心是已有节点，因此也覆盖游戏一轴分支重建内侧扇心的情况。

样本的前三段在原生格坐标中满足：

```text
8x - y = 8
2x - y = -4
9x - 10y = -106
```

前两式推出 `x = 2, y = 8`，代入第三式得到 `-62`，与 `-106` 不符。三个平面已经没有公共点，第四段也无法补救；`z` 不参与这些平面方程。各片正面支撑偏移在本样本中相同，因此平移后的目标玻璃平面仍无公共点。

离线报告的法向矩阵秩为 2，带平面常数的增广矩阵秩为 3，与上述整数方程矛盾一致。把八片直接合成一个外环，或尝试更换外环起点，均不能精确保留指定形状。前次未接入 UI 的 `mergeSurfaceAsFan` 草案及只检查外轮廓的两个测试已撤除；外轮廓一致不能作为曲面等价的证据。

## 双平面降级候选（2026-10-03）

**将目标降级为一个原生面内的两片连接平面，有可行候选。** 当前静态几何路径只为外环生成框；扇形内部对角线无需梁，也不单独内缩。这与多个原生窗相互拼接的路径不同。

扇心必须由游戏能够表达的原生边界起点产生。二/三轴窗的扇心是第一个内缩玻璃顶点，实体面是第一个边界点；JSON 不提供任意内部扇心字段。应选择折线与外边界相交的**已有端点 A**为边界起点，将另一端点 B 放在外环的相应位置。若两个分区都是从 A 可见的简单区域，扇形中 A–B 对角线将分开两侧平面。不能仅根据两个无限平面相交，就把交线内部任意中点写成扇心：内部点不在外边界上，也没有独立字段可传入。

离线重建新增 [single-window-fan.mjs](../scripts/lib/single-window-fan.mjs)，复现当前方向选取、统一支撑偏移、同向共线点筛选、二/三轴玻璃内缩和 `(0,i+1,i)` 扇形。检查各三角所在平面、投影覆盖及玻璃共边。它保留为离线研究模块，未接入编辑器的三角化或普通导出。

### 六点候选与对照

本轮合成六点窗使用下列原生格坐标，不修改用户载具：

```text
A = ( 0, 0,-6)
R0= ( 8, 4,-6)
R1= ( 8, 4, 6)
B = ( 0, 0, 6)
L1= (-8, 4, 6)
L0= (-8, 4,-6)
```

外环 `[A,R0,R1,B,L1,L0]` 保存为**一个** `plates[]` 记录。只创建相邻外环梁，**不创建 A–B 梁**。四个内部三角形为 `[A,R1,R0]`、`[A,B,R1]`、`[A,L1,B]`、`[A,L0,L1]`。前两片和后两片各自共面，两侧共用 A–B 玻璃边。

若只将这份相同外环的起点换成 R0，原生节点扇形与玻璃扇形都变为四个平面。因此合并时必须保存正确原生起点，不能让排序、循环归一化或导出绕序处理任意选择首点。当前真实 Builder 导入/原生导出适配器已通过该候选的重复往返，保留原生位置、起点顺序、六根梁及一个窗。

实体面在统一支撑平移后能精确保留这两个目标平面；窗的内缩使用单一面方向，并不逐片使用各自法线，所以虽然上述候选仍有两个玻璃平面，角度与原始节点平面有差异。在六点示例中，部分玻璃顶点离支撑平移后的原平面约 `0.04851` world units（约 `0.606` 格）。**双平面且无内框不等于精确保留任意指定的两片玻璃平面。** 后续交互预览应显示游戏生成的内缩折面，再让用户调整外环，而不能继续以理想控制节点面代替最终窗几何。
